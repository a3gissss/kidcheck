# DSH Hacks V2: AI x Healthcare Project Development

Act as a senior full-stack software engineer, AI engineer, healthcare technology researcher, UI/UX designer, and hackathon mentor.

Help me design and build a functional, innovative, beginner-friendly project for **DSH Hacks V2**, a global student hackathon themed **AI x Healthcare**.

## 1. Competition Objective

Build a working technical prototype that addresses a real-world healthcare problem using software and, where appropriate, AI.

The project must demonstrate:
- A clearly defined healthcare problem.
- An innovative and practical technical solution.
- Meaningful user interaction.
- Appropriate AI integration.
- Technical depth and feasibility.
- Potential real-world impact.
- A polished user interface and a convincing live demonstration.

The solution can be a website, web application, mobile application, simulation, system, or algorithm.

## 2. My Background and Constraints

Assume I am a student and beginner-to-intermediate web developer who is still developing my programming skills.

My preferences:
- Build a web application unless another format is clearly better.
- Use HTML, CSS, JavaScript, React, and other appropriate technologies.
- Choose a technology stack that is achievable for a student within a hackathon timeframe.
- Prefer free or free-tier development tools and APIs.
- Explain unfamiliar concepts in simple language.
- Provide complete, working code rather than vague instructions or pseudocode.
- Avoid unnecessary complexity and expensive infrastructure.

Do not assume that I have access to hospitals, patient records, medical equipment, paid AI APIs, or clinical datasets.

## 3. First, Identify the Best Project Idea

Before writing any code, propose five original project ideas within AI x Healthcare.

For each idea, explain:
1. The specific healthcare problem.
2. The target users.
3. How the solution works.
4. Where AI adds meaningful value.
5. The core features.
6. The technical difficulty.
7. How it can be demonstrated without real patient data.
8. Its potential impact and competitive advantage.

Prioritize problems affecting underserved communities, students, low-resource healthcare systems, and people with limited access to reliable health information.

Avoid generic symptom-checker chatbots unless the proposed solution offers a genuinely distinctive and demonstrable innovation.

Compare the five ideas based on feasibility, originality, technical depth, safety, and potential impact. Recommend the strongest idea for this competition and explain why.

Wait for my approval before committing to the final idea.

## 4. Design the Approved Solution

Once I approve an idea, develop a detailed project plan containing:

- Project name and memorable tagline.
- Problem statement.
- Proposed solution.
- Target audience.
- Main use cases.
- Key features and user journeys.
- System architecture.
- Technology stack and reasons for choosing it.
- AI model, API, or algorithm to use.
- Data requirements and data sources.
- Privacy, security, and healthcare safety considerations.
- Limitations and future improvements.

Clearly distinguish functional features from proposed future features.

## 5. Build the Application

Develop a functional, responsive application with a professional interface suitable for a global hackathon demonstration.

Requirements:
- A clean landing page explaining the problem and solution.
- An intuitive dashboard or main application interface.
- Working forms, buttons, navigation, and user interactions.
- Input validation and useful error messages.
- Loading, success, empty, and error states where appropriate.
- Responsive layouts for desktop and mobile.
- Accessible design, readable typography, and good contrast.
- Realistic demo data that is clearly identified as synthetic.
- Appropriate AI functionality that demonstrably contributes to the solution.

Do not create a frontend full of nonfunctional buttons or fake AI outputs presented as genuine analysis.

If an external AI service is unavailable, implement a transparent fallback using sample data or a clearly labelled rule-based algorithm. Explain the difference between the fallback and genuine AI functionality.

Use environment variables for API keys. Never expose secrets in frontend code or commit them to GitHub.

## 6. Healthcare Safety and Responsible AI

The application must not make unsupported medical claims or present experimental outputs as definitive diagnoses.

Depending on the selected project:
- Make it clear that the prototype is for educational or research demonstration, not a substitute for qualified medical professionals.
- Use reputable healthcare sources when providing medical information.
- Avoid using real identifiable patient data.
- Explain uncertainty and known limitations.
- Include appropriate escalation guidance for potentially urgent situations.
- Do not claim clinical accuracy without valid evaluation evidence.
- Do not claim regulatory approval or clinical validation unless independently established.

If the project uses predictive AI, explain the model's inputs, outputs, limitations, and how it would be evaluated before real-world deployment.

## 7. Development Workflow

Build the project in small, verifiable stages:

Stage 1: Project structure and setup.

Stage 2: User interface and navigation.

Stage 3: Core functionality.

Stage 4: AI integration or algorithm implementation.

Stage 5: Data handling, validation, and error management.

Stage 6: Testing and debugging.

Stage 7: Deployment.

Stage 8: GitHub repository preparation.

At each stage:
- Tell me which files to create or modify.
- Provide the complete code for each new or substantially changed file.
- Explain exactly where the code belongs.
- Give the terminal commands required.
- Explain how to run the application locally.
- Provide a test checklist and expected results.
- Help me fix errors before moving to the next stage.

Do not skip steps or assume I already understand the setup.

## 8. Required Competition Deliverables

Prepare all the following deliverables after the application is working.

### A. Working Project
A deployed or locally runnable prototype with meaningful user interaction.

### B. GitHub Repository
Prepare:
- A clear repository name.
- A professional README.md.
- Project overview and problem statement.
- Features and technology stack.
- Installation and setup instructions.
- Environment variable documentation using a safe example file.
- Architecture overview.
- Screenshots or demo GIFs.
- Testing instructions.
- Limitations and future improvements.
- An appropriate open-source license, if suitable.

Organize the source code cleanly and exclude secrets, unnecessary dependencies, and generated files.

### C. Demo Video
Write a concise, persuasive demo script of approximately 2–3 minutes containing:
- The opening hook and healthcare problem.
- Why the problem matters.
- The proposed solution.
- A live walkthrough of the main features.
- A demonstration of the AI component.
- The project's potential impact.
- A closing statement.

Include a shot-by-shot recording plan and the exact actions to perform on screen. Demonstrate only features that actually work.

### D. One-Page Project Description PDF
Prepare a polished, single-page project description containing:
- Project title and tagline.
- Problem statement.
- Proposed solution.
- Target users.
- Key features.
- AI and technical approach.
- Expected impact.
- Technologies used.
- GitHub repository and live demo links, when available.

Keep the document concise, visually organized, and understandable to both technical and nontechnical judges.

### E. GitHub Repository / Code PDF
Prepare a PDF document showcasing the actual code developed for the project.

The PDF should include:
- Project title and repository link.
- Brief architecture overview.
- Project folder structure.
- The important source files and their complete, relevant code.
- File names and syntax highlighting where practical.
- Explanations of the most important implementation decisions.
- The AI integration or algorithm.
- Any relevant testing code.

Include the code necessary to understand the implementation, not just screenshots or isolated snippets. Ensure the code corresponds to the final working version in the repository. If the complete code is too long for a readable PDF, include all important files and clearly document where the complete source code can be found.

Use a consistent layout, readable font, page numbers, and a table of contents if necessary.

## 9. Final Quality Checks

Before declaring the project complete:
- Test all major user journeys.
- Verify that the main features actually work.
- Check for console errors and broken links.
- Verify mobile responsiveness.
- Check for exposed API keys and sensitive data.
- Verify that the GitHub repository matches the final build.
- Confirm that the demo video accurately represents the application.
- Confirm that the project description is exactly one page.
- Confirm that the code PDF contains the actual project code.
- List every deliverable and identify any remaining limitations.

## 10. How to Work With Me

Be practical, critical, and honest. Optimize for a project that can be completed, demonstrated, and defended by a student, rather than an ambitious project that never becomes functional.

Start by presenting the five project ideas and your comparison. Do not generate the full application until I approve the recommended idea.
